# Migrate Workspace to ASDLC-Aligned Template (v2)

Run this prompt with an AI agent from the root of a workspace that was initialized with the previous version of this template. It migrates the workspace `AGENTS.md` to the ASDLC anatomy, replaces `CLAUDE.md` with a symlink, and re-audits each repo.

**Prerequisites:** The new template files (`prompts/audit.md`, `prompts/init.md`, `README.md`) must already be in place. This prompt handles the runtime migration — not the file copy.

---

## The Prompt

```
You are migrating this workspace from the original template format to the ASDLC-aligned v2 format.

Work through the following phases in order.

---

### Phase 1: Extract Existing Data

Read the current workspace `AGENTS.md` and extract:

1. **Repository table rows** — every row from the `## Repositories` table (Directory, Repository, Description).
2. **Cross-repo dependencies** — any content under `## Cross-repo Dependencies`.
3. **Any custom content** — sections or notes the user may have added manually beyond the template defaults. Flag these for reinsertion.

Also check:
- Does `CLAUDE.md` exist as a regular file (not a symlink)? Note this for Phase 3.
- Are there repos listed in the table whose directories no longer exist? Flag these as stale.

---

### Phase 2: Rewrite Workspace AGENTS.md

Rewrite `AGENTS.md` using the ASDLC anatomy. Use this structure:

```markdown
# AGENTS.md

> **Project:** <infer from workspace directory name and repository descriptions>
> **Core constraint:** Each repo is independently versioned and gitignored — the workspace tracks only orchestration files and agent context.

## Toolchain

| Action | Command | Notes |
|---|---|---|
| Init workspace | Run `prompts/init.md` | Discovers repos, populates this file, audits each repo |
| Add repo | Run `prompts/add-repo.md` with clone URL | Clones, registers, audits in one step |
| Audit repo | Run `prompts/audit.md` from repo root | Generates `docs/agents/` (human reference) and `AGENTS.md` |
| Remove repo | Delete directory, re-run `prompts/init.md` | Cleans up stale entries |

## Judgment Boundaries

**NEVER**
- Commit secrets, tokens, connection strings, or internal URLs to any file
- Modify a repo without first reading its `AGENTS.md`
- Guess at repo structure or conventions — read actual files

**ASK**
- Before running destructive operations (force push, reset, branch deletion)
- Before adding cross-repo dependencies
- Before modifying workspace-level files (`AGENTS.md`, `.gitignore`) outside of prompts

**ALWAYS**
- Read the target repo's `AGENTS.md` before making changes in it
- Use environment variable *names* only in documentation — never values
- Return to workspace root before switching to another repo

## Repositories

| Directory | Repository | Description |
|---|---|---|
<insert extracted rows here, removing any stale entries>

## Cross-repo Dependencies

<insert extracted cross-repo dependency content, or:>

## Context Map

```yaml
workspace:
  AGENTS.md: "This file — workspace-level agent constitution (symlinked as CLAUDE.md)"
  prompts/:
    init.md: "First-time workspace setup — discovery, registration, audit"
    add-repo.md: "Add a single repo — clone, register, audit"
    audit.md: "Audit a single repo — generates docs/agents/ and AGENTS.md"
  docs/: "Reserved for workspace-level documentation"

per-repo (generated by audit):
  AGENTS.md: "Repo-level agent constitution — minimal, judgment-layer only"
  docs/agents/: "Detailed human reference docs — NOT agent context, read on demand"
```
```

If custom content was flagged in Phase 1, find the appropriate place for it in the new structure (likely Judgment Boundaries or Context Map). If it doesn't fit, append it as a clearly labeled `## Project-specific Notes` section at the bottom.

If the workspace directory name or repository descriptions suggest a more specific Mission line than the generic default, use it.

---

### Phase 3: Fix CLAUDE.md Symlink

If `CLAUDE.md` exists as a regular file (not a symlink):

1. Delete the file.
2. Create a symlink: `ln -s AGENTS.md CLAUDE.md`
3. Verify the symlink works by reading `CLAUDE.md` and confirming it matches `AGENTS.md`.

If `CLAUDE.md` is already a symlink to `AGENTS.md`, skip this phase.

---

### Phase 4: Re-audit Each Repository

For each repository listed in the Repositories table:

1. Verify the directory exists. Skip if it doesn't (it was already flagged as stale).
2. Change into the repo directory.
3. Read `prompts/audit.md` from the workspace root and execute all its phases. The audit will:
   - Preserve and update existing `docs/agents/` files (incremental update).
   - **Rewrite `AGENTS.md`** to the new minimal, ASDLC-aligned format (judgment-layer only).
4. Return to the workspace root before moving to the next repo.

> **Context limits:** For workspaces with many repositories (4+), re-auditing all repos in a single session may hit context limits. In that case, complete Phases 1–3 in this session, then audit repos individually by running `prompts/audit.md` from each repo's root in separate sessions.

---

### Phase 5: Update Cross-repo Dependencies

After all audits are complete, review each repo's `docs/agents/overview.md` for the **Cross-repo dependencies** section. Update the workspace `AGENTS.md` `## Cross-repo Dependencies` section:

1. List each dependency relationship as: `<consumer>` → `<provider>` with a short description of what is consumed.
2. If no cross-repo dependencies exist, note "No cross-repo dependencies detected."

---

### Phase 6: Validate

1. Read the final workspace `AGENTS.md` and verify:
   - All repository rows point to directories that exist.
   - The symlink `CLAUDE.md` → `AGENTS.md` is in place.
   - No secrets, tokens, or internal URLs are present.
2. For each repo, verify its `AGENTS.md` follows the ASDLC anatomy (Mission, Toolchain, Judgment Boundaries, Context Map, Human Reference table).
3. Report what changed — list repos that were re-audited and any stale entries that were removed.

---

### Guidelines

- **Read before writing.** Don't assume — open files and verify.
- **Preserve user additions.** If the user added custom content to the old `AGENTS.md`, migrate it to the new structure.
- **Don't lose repository rows.** The table is the critical data — extract it carefully.
- **Flag stale entries.** If a repo directory no longer exists, remove the row and report it.
- **Disclosure:** No secrets, env *names* only, no private/internal URLs.
```
